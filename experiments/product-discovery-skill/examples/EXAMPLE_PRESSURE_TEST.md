# Example — Existing Idea Pressure Test

## User

I want to build a polished desktop utility that automatically beautifies screenshots. The UI would be much better than existing apps.

## Good skill behavior

Do not immediately say either "crowded" or "go for it."

Example reasoning structure:

1. Clarify the actual user and trigger: developer sharing product screenshots, marketer making launch assets, support team annotating bugs, etc.
2. Define the desired transformation and why unusually good output matters.
3. Ask whether the reason-to-win is truly visual craft or whether there is a narrower workflow the incumbents serve poorly.
4. Search exact current competitors only after the proposition is specific.
5. Evaluate whether the product has structural distribution: shareable output, marketplace discovery, creator-demo fit, high-intent search.
6. If exact alternatives already match the same user/workflow and the only advantage is "prettier," recommend narrowing or a very cheap experiment rather than a full build.
7. If a distinct workflow remains and craft leverage is genuinely high, define the smallest polished slice capable of testing preference/payment.

The output is a decision and experiment, not merely a competitor list.
