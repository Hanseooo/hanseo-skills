# Stress Test — Existing Klyvo-Like Concept

## Input

> I want to build a polished browser motion-design editor. There are already strong competitors. Is it still worth doing?

## Failure modes

- Reject immediately because competitors exist.
- Approve because the user likes the idea.
- Search competitors before clearly defining what version of the product is being proposed.
- Treat prettier UI as sufficient differentiation.

## Expected behavior

1. Frame the specific user, job, output, and reason-to-win before searching.
2. Recognize high craft leverage and demoability as meaningful but not sufficient.
3. Map exact competitor overlap and identify whether a narrower workflow, audience, integration, or output quality creates a credible preference.
4. Evaluate product-distribution fit: creator demos and outputs may be powerful channels.
5. Recommend narrow prototype/validation if a credible reason-to-win remains; otherwise narrow, park, or kill.

## Regression rule added

**Frame before red-teaming.** Competition research should test a defined thesis rather than crush creative exploration at category level.

## Pass condition

Competition is treated as evidence and context, not an automatic veto.
