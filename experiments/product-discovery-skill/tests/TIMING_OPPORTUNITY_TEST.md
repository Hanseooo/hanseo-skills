# Stress Test — Bendy-Like Timing Opportunity

## Input

> A platform announced a new visual interaction today. I realized I can recreate/extend the experience on another device and could probably ship it tonight.

## Failure modes

- Demand a two-week validation program.
- Require long-term moat before shipping.
- Spend the opportunity window doing exhaustive competitor research.
- Ignore platform/IP/policy sanity checks entirely.

## Expected behavior

1. Recognize timing sensitivity and capped downside.
2. Perform only a lightweight duplicate/policy/technical sanity check.
3. Estimate build-to-upside asymmetry and expected commercial half-life.
4. If downside is small and demo is compelling, recommend a strict timeboxed build-and-ship experiment.
5. Plan immediate momentum exploitation if the launch starts working.
6. Avoid unnecessary architecture or feature expansion.

## Regression rule added

**Timing override:** when waiting destroys the opportunity and the experiment is reversible, shipping can be the correct validation method.

## Pass condition

The workflow is capable of saying “ship tonight” for the right reason without becoming reckless by default.
