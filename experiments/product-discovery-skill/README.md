# Product Discovery Skill

A reusable, agent-friendly workflow for independent software product discovery, ideation, research, pressure-testing, validation, and post-launch learning.

## Philosophy

This skill is **highly adaptive and collaborative by default**.

It does not assume that the best product must:
- solve severe pain;
- have no competitors;
- be SaaS;
- be local-first;
- use AI;
- be subscription-based;
- be a one-time purchase;
- have a five-year moat;
- undergo the same validation process as every other idea.

Instead, it tries to understand the decision being made and select an appropriate workflow.

## Core idea

The skill repeatedly asks four questions:

1. **What value does the user actually want?**
2. **Why would this particular version deserve preference?**
3. **How would the right users discover and understand it?**
4. **What is the cheapest credible way to reduce the most important uncertainty?**

## Folder map

- `SKILL.md` — operational behavior and routing.
- `principles/` — durable reasoning principles and evidence rules.
- `workflows/` — research, validation, and post-launch operating modes.
- `references/` — reusable lenses derived from studied indie-product patterns.
- `tests/` — regression/stress tests used to keep the workflow from becoming biased.
- `examples/` — example conversations showing the intended behavior.

## Important design choice

The case studies behind this skill include commercially validated products, highly polished craft references, community-popular products, and counterexamples. They are intentionally not treated as equivalent evidence.

The skill should remain useful even when the named examples age or disappear because the workflow is based on transferable mechanisms rather than copying product categories.

## Version

`0.1.0` — first packaged version after a five-scenario pressure test plus a post-launch regression test.
